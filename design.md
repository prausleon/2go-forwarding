# 2GO Forwarding Wireframe Design System

## Purpose

A low-fidelity-to-mid-fidelity HTML wireframe system for validating information architecture, content hierarchy, conversion and SEO/GEO/LLMO before production visual design.

## Visual direction

- Corporate, confident, modern logistics aesthetic.
- Strong blue-led brand direction with yellow accent based on recognizable 2GO visual language; exact production tokens should be validated against current brand guidelines.
- Large typography and generous whitespace.
- Modular cards for services and industries.
- Strong use of numbers, route/network proof and operational diagrams.
- Avoid generic stock-logistics visual overload.
- Use real 2GO assets only when approved.

## Layout

- Tailwind CSS utility classes.
- Max content width: approximately 1280px.
- 5px horizontal mobile gutters / 20–24px desktop equivalent.
- 8px-ish spacing rhythm.
- Rounded cards used for hierarchy, not decoration.
- Responsive first; mobile navigation should become an accessible menu in production.

## Page template: service

1. Breadcrumb
2. H1 + one-sentence definition
3. Primary CTA
4. Key facts
5. What the service solves
6. Service options / variants
7. Cargo types
8. Coverage / network
9. How it works
10. Capabilities / infrastructure
11. Industries
12. FAQs
13. Related services
14. Quote CTA

## Page template: industry

1. Industry problem statement
2. Logistics challenges
3. Recommended 2GO solutions
4. Service workflow
5. Specialized capabilities
6. Network / coverage
7. FAQs
8. CTA

## Page template: network

Use real geographic entities in text and accessible map/list representations. Do not rely exclusively on an image map.

## Wireframe content rules

- Preserve source terminology such as FCL, LCL, RORO, RDU, BSA, LTL and FTL.
- Never invent prices, schedules, SLAs, certifications or coverage.
- Mark claims needing validation before launch.
- Prefer concise paragraphs and scannable lists.
- Put commercial CTAs near decision points.
