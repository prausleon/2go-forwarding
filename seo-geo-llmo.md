# 2GO Forwarding SEO / GEO / LLMO Strategy

## Strategic objective

Make 2GO Forwarding highly discoverable for both conventional search and AI-generated answers around Philippine freight forwarding, sea freight, air freight, land transportation, LCL consolidation, cold chain, pharma, retail/mall logistics and specialized cargo.

## SEO foundations

- One canonical, indexable URL per core service.
- Descriptive title tags and meta descriptions using service + Philippine context where appropriate.
- Exactly one clear H1 per page.
- Semantic H2/H3 hierarchy.
- Crawlable internal links between services, industries, network pages and FAQs.
- Breadcrumbs on deep pages.
- XML sitemap and clean robots.txt.
- Canonical URLs.
- Optimized WebP/AVIF imagery with width/height and lazy loading below the fold.
- Minimal JavaScript; prefer server-rendered/static HTML.
- Strong Core Web Vitals and mobile-first layout.
- Accessible navigation, forms, headings, links and contrast.

## GEO — Generative Engine Optimization

The goal is not keyword stuffing. Build pages that are easy for retrieval and synthesis systems to understand.

### Entity clarity

Explicitly establish:
- 2GO Forwarding
- 2GO
- Philippines
- services
- ports
- facilities
- fleet
- industries
- specialized solutions

### Answer-first sections

Every service page should include a concise definition block:

"What is [service]?"
"Who is it for?"
"When should a business use it?"
"What cargo can it handle?"
"Where is it available?"
"How does the process work?"

### Evidence blocks

Use structured facts and source-backed proof points such as network size, ports, container/reefer capability, facility size and service capabilities. Add a visible "Last updated" date for volatile operational facts.

### Question-led content

Create FAQ sections that answer real customer questions in 40–80 word direct answers, followed by supporting detail.

## LLMO — Large Language Model Optimization

- Use consistent terminology across every page.
- Avoid vague marketing-only copy.
- Put important facts in HTML text, not images.
- Provide explicit relationships: service → cargo → geography → customer → capability.
- Use tables for route, mode and capability comparisons where appropriate.
- Include short definitions before long explanations.
- Add internal links using descriptive anchor text.
- Maintain an authoritative About / Network page that establishes organizational context.
- Add Organization, WebSite, Service, BreadcrumbList, FAQPage and relevant LocalBusiness/Place structured data only when applicable and accurate.
- Use sameAs/entity links only for official, verified properties.
- Keep structured data synchronized with visible page content.
- Consider a machine-readable service directory/data layer later, but do not create unsupported claims.

## Trust / E-E-A-T

- Show operational expertise without inventing certifications.
- Attribute claims to current 2GO sources internally during content governance.
- Use named facilities, routes and capabilities when verified.
- Keep stale operational figures out of evergreen copy.
- Provide transparent contact and inquiry paths.

## Technical content rules

- No important copy embedded in hero images.
- No service information hidden behind JavaScript-only interactions.
- Avoid giant client-side bundles.
- Use static/server-rendered pages.
- Optimize fonts and avoid unnecessary third-party scripts.
- Provide meaningful alt text.
- Use descriptive slugs.
- Implement 301 redirects for legacy URLs during migration.

## Measurement

Track:
- Organic impressions/clicks by service
- Non-brand query growth
- Indexed service pages
- Rich-result eligibility
- AI referral traffic where measurable
- Brand/entity mentions in AI answers through periodic manual sampling
- Quote CTA conversion rate
- Form completion rate
- Core Web Vitals
